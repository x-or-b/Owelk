# Owelk

개인과 동료의 논문 읽기를 위한 로컬 데스크톱 앱. 현재는 **macOS에서 검증 중인 개발용 프로토타입**이며, 기획서 전체가 구현된 상태는 아닙니다.

## 실행

기존 창을 닫은 뒤 프로젝트에서 다음 명령으로 실행합니다. 현재 수동 테스트 데이터와 읽던 위치를 그대로 사용합니다.

```sh
open -n /Users/gyu/Documents/Owelk/build/owelk.app --args --data-dir /Users/gyu/Documents/Owelk/build/manual-data
```

`--data-dir` 없이 실행하면 OS의 앱 데이터 폴더를 사용하므로, 위 테스트 데이터와 별도로 저장됩니다. 여러 인스턴스를 같은 데이터 폴더로 실행하지 마세요.

## 현재 기능

- Home: 중앙 검색, Continue Reading, Recent Workspaces, Recent Papers
- 이름 있는 읽기 워크스페이스 생성·전환 및 마지막 두 문서의 읽기 상태 저장
- 두 PDF 나란히 읽기(현재 최대 2개), 페이지 이동
- `⌘/Ctrl+F`로 문서 내 검색창 열기, Esc 또는 ×로 닫기 (기본은 숨김)
- 마우스·트랙패드 문장 선택 및 복사, 줄 전체를 기준으로 높이를 고정한 선택 표시 (대문자·소문자·아래로 내려오는 글자를 추가해도 높이 유지)
- Ctrl+휠 확대·축소, macOS에서는 ⌘+휠도 지원. 수식키 없는 휠은 스크롤
- 영역 캡처 저장 및 원문 위치로 돌아가기
- 캡처 원본의 SHA-256 검증: 파일이 바뀌면 잘못된 출처로 이동하지 않도록 중단
- 최근 문서, 창 구성과 읽던 위치 복원
- 기본 커맨드 팔레트: macOS `⌘K`, Linux/Windows `Ctrl+K`
- 영어 UI, 닫거나 좌우로 이동할 수 있는 Files / Captures 패널
- 선택한 폴더의 PDF·하위 폴더 탐색 (읽기 전용, 펼칠 때 비동기로 불러오기)

## 패널 사용

- 하단 상태 표시줄의 폴더/그림 아이콘으로 Files / Captures를 열거나 닫습니다. 아이콘 위에 잠시 머무르면 설명이 표시됩니다. 패널 제목 옆 `×`로도 닫습니다.
- 아이콘을 **하단 상태 표시줄 안에서** 왼쪽 또는 오른쪽 절반으로 끌어 놓으면 패널 위치가 바뀝니다. 회색으로 표시되는 위치를 확인하고 놓으세요. Esc 또는 표시줄 밖에 놓으면 취소됩니다.
- 닫힌 패널의 아이콘도 옮길 수 있고, 옮겨도 닫힌 상태는 유지합니다. 두 패널이 같은 쪽이면 아이콘이나 제목 탭으로 전환합니다.
- `Files`는 처음에는 최근 PDF를 표시합니다. `Open folder…`로 폴더를 선택하면 하위 폴더와 PDF 목록을 표시합니다. `↻`로 새로 고칩니다.
- 원본 파일은 변경하지 않으며, 숨김 파일·심볼릭 링크는 목록에서 제외합니다. 파일 생성·이동·삭제 기능과 폴더 전체 본문 검색은 아직 없습니다.
- 패널의 위치·열림 상태·선택한 루트 폴더는 재실행 시 복원합니다. 하위 폴더의 펼침 상태는 아직 저장하지 않습니다.

문서 제목을 드래그해 PDF를 분할하는 기능과 **사이드 패널 이동**은 다릅니다. 현재 구현한 것은 사이드 패널 이동입니다.

## Home 사용

- 복원할 문서가 없으면 Home으로 시작합니다. 하단 집 아이콘, `⌘/Ctrl+Shift+H`, `/home`으로 언제든 돌아갑니다. 종료 시 Home을 보고 있었다면 재실행해도 Home을 표시합니다.
- 중앙 검색은 지금까지 연 PDF의 **파일명**, 저장한 캡처의 **출처 파일명·페이지**, **워크스페이스 이름**을 찾습니다. 결과 종류를 표시하며 클릭 또는 방향키·Enter로 엽니다. 폴더 전체 PDF를 자동 등록하거나 본문을 검색하지는 않습니다.
- Continue Reading은 마지막 활성 문서의 페이지·스크롤·배율을 복원합니다. 최근 PDF도 개별 읽기 위치를 기억합니다.
- Recent Workspaces 옆 `+`로 이름을 지정해 만듭니다. 지금의 워크스페이스는 문서 연결과 마지막 두 문서의 읽기 상태를 저장하는 초기 버전입니다. 전체 연결 문서 목록, 노트·캡처 연결 편집, 이름 변경·삭제는 후속 작업입니다.
- Recent Papers는 최근 12개, Recent Workspaces는 최근 12개를 표시합니다. 검색은 이 최근 표시 개수 밖의 저장된 항목도 찾습니다(종류별 최대 20개 결과).
- 네이티브 다중 창과 새 창 전용 Home 흐름은 아직 없습니다. 같은 데이터 폴더를 여러 앱 인스턴스에서 동시에 열지 마세요.

커맨드 팔레트의 일반 입력은 **최근 PDF의 파일명 검색**입니다. 라이브러리 전체 본문 검색은 아직 아닙니다. 방향키로 이동하고 Enter로 실행하며 Esc로 닫습니다.

| 명령 | 동작 |
| --- | --- |
| `/home` | Home 화면으로 이동 |
| `/open paper` | PDF 열기 또는 최근 문서 선택 |
| `/open paper 검색어` | 최근 PDF 파일명 검색 |
| `/find` | 활성 문서의 검색창으로 이동 (Home에서는 중앙 검색) |
| `/files` | 파일 패널 표시 |
| `/split right` | 나란히 읽기 켜기 |
| `/split off` | 왼쪽 문서만 보기 |
| `/capture` | 영역 캡처 모드 전환 |
| `/captures` | 저장된 영역 캡처 목록 열기. 항목을 누르면 원문 위치로 이동 |

`/capture`는 새 캡처를 만드는 모드이고, `/captures`는 이미 저장한 캡처 목록을 여는 명령입니다. `/caputres` 오타도 `/captures`로 처리합니다.

휠 확대는 앱이 휠 이벤트를 전달받았을 때 동작합니다. 핀치(두 손가락을 벌리거나 오므리기)의 실시간 부드러운 확대는 별도 후속 작업입니다. macOS의 Command/Control 매핑은 [Qt 플랫폼 문서](https://doc.qt.io/qt-6/qt.html#KeyboardModifier-enum)에 맞춰 처리합니다. Windows/Linux 실기기 검증은 아직 하지 않았습니다.

## 빌드와 테스트

C++20, CMake 3.24 이상, Qt 6.9 이상이 필요합니다. 현재 macOS에서 Qt 6.11.2로 빌드·테스트합니다.

```sh
brew install cmake qtbase qtdeclarative qtwebengine
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_PREFIX_PATH=/opt/homebrew
cmake --build build --parallel 6
ctest --test-dir build --output-on-failure
```

Qt PDF는 Homebrew의 `qtwebengine`에 포함됩니다. 현재 앱은 PDF 모듈을 사용하며, 웹 브라우저는 아직 구현하지 않았습니다. Intel Mac이나 다른 OS에서는 Qt 설치 경로를 맞춰야 합니다. Linux/Windows의 실제 실행은 아직 검증하지 않았습니다.

테스트는 임시 PDF와 데이터 폴더를 만들고, 데스크톱 조작 없이 offscreen Qt 창에서 실행합니다. 저장·출처 검증, PDF 렌더링, 입력 장치별 선택·복사, 안정된 줄 높이, 검색·위치 복원, 팔레트 입력, 하단 아이콘 클릭·드래그·취소·복원, 폴더 펼침, Home 검색·이어 읽기·워크스페이스 전환을 검사합니다. 테스트 통과가 실제 장치에서의 사용성 검증을 대신하지는 않습니다.

## 데이터와 한계

지정한 데이터 폴더의 `owelk.sqlite3`에 세션·문서별 위치·워크스페이스·캡처 출처를, `captures/`에 PNG를 저장합니다. 원본 PDF는 복사하거나 수정하지 않고 기존 경로로 참조합니다. 원본을 이동하면 자동 재연결하지 않습니다. 저장된 캡처 이미지는 유지됩니다.

현재 API 호출·로그인·외부 업로드는 없습니다. PDF의 웹 링크를 누르면 시스템 브라우저에서 열립니다. AI, 웹 탭, OCR, 영구 하이라이트·노트, 백업 UI, 파일 재연결 UI는 아직 미구현입니다. 여러 페이지를 가로지르는 텍스트 선택과 암호 PDF의 영역 캡처도 아직 지원하지 않습니다.

## 이어서 할 작업

1. 여러 PDF를 전환하는 탭·탐색 구조와 탭별 읽던 위치 보존
2. 고정 2분할을 분할 트리로 교체해 임의 개수의 가로·세로 분할 지원
3. 탭/문서 제목을 끌어 가장자리에 놓으면 분할, 중앙에 놓으면 해당 그룹으로 이동
4. 핀치 확대·축소 개선: 현재는 제스처 종료 후 배율을 반영합니다. 제스처 중에는 임시 화면 변환을 적용하고, 종료 후 선명하게 다시 렌더링하는 방식과 손가락 중심점 유지 구현이 필요합니다.
5. 실사용 PDF에서 성능 측정, Home 검색을 본문·노트·웹까지 확장

문서 탭·드래그 분할은 아직 미구현입니다. 다음 작업의 데이터 구조와 검증 조건은 [개발 작업 목록](docs/NEXT.md)에 기록합니다. UI 번역 설정은 후속 작업이며 현재 인터페이스는 영어입니다.

불필요한 상단 앱 이름 바는 제거했고, 기본 탐색·패널 조작은 하단 상태 표시줄로 모았습니다. 기획서와 구현의 차이는 [진행 현황](docs/STATUS.md)을 참고하세요.
