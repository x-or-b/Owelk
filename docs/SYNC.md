# 컴퓨터 사이 동기화

Mac과 Ubuntu처럼 여러 컴퓨터에서 같은 라이브러리를 씁니다. 서버나 계정은 따로 없습니다. Google Drive, Dropbox, Syncthing, 네트워크 공유처럼 **다른 프로그램이 컴퓨터끼리 맞춰 주는 폴더**를 하나 고르면, Owelk는 그 폴더에 변경 기록과 PDF를 놓고 읽어 옵니다.

## 켜기

1. 각 컴퓨터에서 공유 폴더 프로그램을 설치하고, 같은 폴더가 양쪽에 보이게 합니다(아래 Google Drive 참고).
2. Owelk **Settings → Data → Sync → Choose Folder…**에서 **클라우드 드라이브 안의 폴더**를 고릅니다(예: Google Drive의 `My Drive`).
   - Owelk는 고른 폴더 안에 항상 `Owelk` 폴더를 만들고 그 안에만 씁니다. 이름이 `Owelk`인 폴더를 직접 고르면 그 폴더를 씁니다. 그래서 두 컴퓨터에서 모두 `My Drive`를 고르면 같은 `My Drive/Owelk`를 씁니다.
   - 이 폴더는 컴퓨터끼리 주고받는 **우편함**입니다. 논문을 보관하는 폴더가 아니므로 PDF를 직접 넣거나 옮길 필요가 없습니다. Library에 있는 논문의 PDF는 Owelk가 알아서 공유 폴더의 `Owelk/Papers`에 **복사**합니다(원본과 내 컴퓨터의 보관 폴더는 그대로).
   - 그냥 내 컴퓨터의 폴더(예: `Desktop/Papers`)를 고르면 다른 컴퓨터가 볼 수 없으므로 동기화되지 않습니다.
3. 다른 컴퓨터에서도 같은 폴더를 고릅니다. 처음 한 번은 라이브러리 전체와 PDF를 옮기므로 시간이 걸립니다.

이후에는 실행 중 30초마다, 종료할 때 자동으로 맞춥니다. **Sync Now**로 바로 맞출 수도 있습니다. 같은 행에 마지막 동기화 시각, 아직 도착하지 않은 파일 수, 함께 쓰는 컴퓨터 이름이 보입니다.

### Google Drive

- **macOS**: [Google Drive for desktop](https://www.google.com/drive/download/)을 설치하면 Finder에 `Google Drive/My Drive`가 생깁니다. 그 안의 `Owelk` 폴더(또는 `My Drive`)를 고릅니다. 오프라인에서도 쓰려면 해당 폴더를 우클릭 → *Available offline*을 켭니다.
- **Ubuntu**: Google의 공식 앱이 없으므로 둘 중 하나를 씁니다.
  - **rclone**(무료): `sudo apt install rclone` → `rclone config`로 `gdrive` 원격 추가 → `rclone mount gdrive: ~/GoogleDrive --vfs-cache-mode full --daemon`. 로그인할 때마다 켜지도록 systemd 사용자 서비스나 시작 프로그램에 같은 명령을 넣습니다. Owelk에서는 `~/GoogleDrive/Owelk`(또는 `~/GoogleDrive`)를 고릅니다.
  - **Insync**(유료, 설정이 쉬움): 동기화할 폴더에 `Owelk`를 넣고 그 로컬 폴더를 고릅니다.
  - GNOME 온라인 계정의 Google Drive는 파일 하나하나가 느려서 권하지 않습니다.
- rclone 마운트가 꺼져 있으면 빈 폴더만 남는데, Owelk는 폴더 안의 `owelk-sync.json` 표식이 처음 고른 것과 같을 때만 읽고 쓰므로 그 상태에서는 아무것도 하지 않고 "The sync folder is not available"을 보여 줍니다.

### 다른 방법

- **Syncthing**: 두 컴퓨터가 직접 주고받습니다(클라우드 없음, 무료). 양쪽 모두 켜져 있을 때 옮겨집니다.
- **Dropbox**: macOS·Ubuntu 모두 공식 앱이 있습니다.

## 옮겨지는 것

**Library에 들어 있는 논문**이 옮겨집니다. 이미 PDF를 모아 둔 폴더(예: `Desktop/Papers`)가 있다면 Library에서 그 폴더를 추가하면 됩니다(`Add Folder…`). `Keep PDFs in Owelk`(기본 켜짐)이면 Owelk가 PDF를 자기 보관 폴더에 복사해 두고 원래 파일은 그대로 둡니다.

| 옮김 | 각 컴퓨터에 남음 |
| --- | --- |
| 논문 목록과 정보(제목·저자·읽기 상태·즐겨찾기), PDF 파일 | 설정(테마·단축키·AI 키·다운로드 폴더 등) |
| 하이라이트·코멘트·텍스트·그림·펜·영역 주석 | 지금 열린 탭(세션), 편집 중 초안 |
| 노트와 링크, Collection·Tag | 검색 색인·의미 벡터(각자 PDF로 다시 만듦) |
| 최근 논문·읽던 위치, AI 대화와 Thread(Manual 정렬로 정한 순서 포함) | 원본 재연결 기록 |
| 읽은 시간(컴퓨터마다 따로 기록해 합산) | |
| Gloss 단어장(Words) | |

- 다른 컴퓨터에서 온 PDF는 Owelk 보관 폴더(`문서/Owelk Library/Papers`)에 원래 파일 이름으로 복사됩니다.
- PDF가 아직 공유 폴더에 도착하지 않았으면 논문은 먼저 목록에 나타나고, 파일은 도착하는 대로 복사됩니다("waiting for N files").
- 양쪽에 **같은 PDF**(바이트가 같은 파일)가 이미 있었다면 하나의 논문으로 합치고 양쪽 주석을 모두 남깁니다. 이름이 같은 Tag도 하나로 합칩니다.

## 충돌

같은 항목(노트 하나, 주석 하나, 논문 정보 하나)을 두 컴퓨터에서 고쳤다면 **나중에 고친 쪽**이 남습니다. 서로 다른 항목은 모두 유지됩니다. 한쪽에서 지우고 다른 쪽에서 고친 경우에도 나중 쪽이 남습니다. 컴퓨터 시계가 크게 틀리면 순서가 어긋날 수 있으니 자동 시간 맞춤을 켜 둡니다.

- 다른 컴퓨터의 변경 하나를 이 컴퓨터에서 적용할 수 없으면(예: 같은 이름의 Tag가 이미 있는데 다른 Tag를 그 이름으로 바꾼 경우) 그 변경만 건너뛰고 상태 줄에 개수를 보여 줍니다. 나머지 변경은 그대로 옮겨지고, 건너뛴 항목은 다음에 다시 바뀔 때 맞춰집니다.
- 논문 지우기: **Delete Paper**는 Owelk Trash로 옮기는 것이라 다른 컴퓨터에서도 Trash로 가고, 공유 폴더의 PDF는 되살릴 수 있게 남습니다. Trash에서 **완전히 삭제**하면(직접 또는 정한 날짜가 지나서) 모든 컴퓨터에서 논문이 사라지고, 각 컴퓨터가 보관하던 사본은 그 컴퓨터의 휴지통으로 갑니다. 그 PDF를 쓰는 논문이 Library와 Trash 어디에도 없으면 공유 폴더의 `Papers/<SHA-256>.pdf`도 지워져서, 동기화 프로그램이 다른 컴퓨터(iPad 포함)의 폴더에서도 지웁니다. 같은 PDF의 다른 사본이 Library에 남아 있으면 PDF도 남습니다. Library에서 빼기만 한 논문(Remove from Library, 중복 사본 합치기, 파일이 없어진 논문 빼기)은 그 PDF를 붙잡지 않고, 완전히 삭제할 때 같은 PDF의 이런 숨은 항목도 함께 지워집니다. 그래서 같은 PDF를 다시 받으면 하이라이트·주석·읽던 위치·읽기 상태·컬렉션·태그 없이 새 논문으로 시작합니다. 노트, 단어장, AI 대화, 읽은 시간 기록은 남고 노트와 논문 사이의 연결만 사라집니다.
- Library에 있는 논문의 PDF가 공유 폴더에 없으면(다른 컴퓨터가 막 지웠는데 이 컴퓨터에서는 아직 쓰는 경우 등) 이 컴퓨터의 사본을 다시 넣습니다.
- 동기화를 켠 채 백업을 복원하면, 그 컴퓨터는 새 컴퓨터처럼 들어와 다른 컴퓨터들의 최신 상태로 다시 맞춰집니다(백업 이후의 변경도 돌아옵니다). 지운 것을 되살리려면 먼저 Library › Trash를 봅니다. 데이터 폴더를 다른 컴퓨터로 복사해 써도 두 컴퓨터는 서로 다른 컴퓨터로 구분됩니다.
- Owelk를 업데이트한 뒤 첫 동기화는 모든 컴퓨터의 변경 기록을 한 번 다시 읽습니다. 예전 버전이 몰라서 지나쳤던 새 항목·값이 이때 채워집니다. 기록이 많으면 이 한 번은 시간이 걸립니다.
- 기록이 긴 경우(처음 동기화 등)에는 변경을 200개씩 나눠 저장합니다. 그 사이에도 이 컴퓨터에서 계속 편집할 수 있습니다. 도중에 Owelk를 끄면 다음 동기화가 멈춘 곳부터 이어 읽습니다.

## 폴더 구조

```
Owelk/
  owelk-sync.json          라이브러리 표식
  devices/<컴퓨터 ID>/       컴퓨터마다 자기 변경 기록(*.jsonl)만 씀
  Papers/<SHA-256>.pdf     PDF
  Files/annotations        그림 주석 이미지
```

각 컴퓨터가 자기 폴더에만 쓰므로 Drive가 "충돌 사본"을 만들 일이 없습니다. 이 폴더의 파일을 직접 고치거나 지우지 마세요. 동기화를 끄려면 **Turn Off**를 누릅니다(공유 폴더와 데이터는 그대로). 다시 켜면 그동안의 변경도 함께 옮깁니다.

## iPad

iPad 앱(`ios/`, 설치와 구조는 [ios/README.md](../ios/README.md))은 같은 폴더에 **컴퓨터 한 대로** 참여합니다. iPad에서는 Synctrain(Syncthing 앱)이 폴더를 맞추고(iCloud는 Ubuntu에 닿지 않으므로 쓰지 않음), 앱에서 파일 앱으로 그 `Owelk` 폴더를 한 번 고릅니다.

- 라이브러리·Collection·Tag·최근 논문·읽던 위치와 모든 주석(하이라이트·코멘트·텍스트·그림·펜·영역)을 읽어 보여 줍니다. 같은 PDF(SHA-256)의 논문은 하나로 보입니다.
- iPad가 써 보내는 것은 **읽던 위치, 연 시각, iPad에서 추가한 논문, Apple Pencil 펜 획과 지운 표시, 글자 하이라이트·코멘트, 표시의 색·메모 바꾸기, Favorites·읽기 상태, Tag·Collection 넣고 빼기와 새 Tag·Collection, 노트와 노트의 링크**이고, iPad 자기 폴더 `devices/<iPad ID>/`와 `Papers/`에만 씁니다. Mac에서 그 논문을 열면 iPad에서 읽던 쪽으로 가고, 확대 방식은 Mac 것을 그대로 씁니다. Settings › Sync의 함께 쓰는 컴퓨터에 "iPad"가 보입니다.
- iPad에서 추가한 PDF(파일 앱에서 고르거나 끌어다 놓기)는 컴퓨터의 Library에 원래 파일 이름으로 복사되고, 보고 있던 Collection·Tag에도 들어갑니다. 저자·연도 같은 정보는 컴퓨터가 다음에 실행할 때나 그 논문을 열 때 PDF에서 읽어 채웁니다. 이미 있는 PDF는 다시 들어가지 않습니다.
- iPadOS는 다른 앱의 폴더 변경을 알려 주지 않아서, 앱이 앞으로 올 때·30초마다·목록을 당길 때 폴더를 다시 읽습니다.
- 데스크톱과 iPad가 같은 형식을 쓰는지는 양쪽 테스트가 같은 파일(`tests/data/sync`)로 확인합니다.

## 한계

- 변경 기록은 지우지 않고 쌓입니다(텍스트라 작음). 지운 것도 "지웠다"는 줄이 하나 더 쌓입니다. 기록과 그림 주석 이미지 정리는 후속 범위입니다.
- 원래 컴퓨터에서 PDF를 다른 버전으로 재연결해도 다른 컴퓨터의 사본은 바꾸지 않습니다.
- iPad 앱이 쓰는 주석은 펜 획과 글자 하이라이트·코멘트이고(지우개는 펜 획만 지움), 영역 표시·글상자·그림은 컴퓨터에서 씁니다. iPad의 하이라이트는 PDFKit의 글자 위치(`start_index`·`end_index`)를 써서, 같은 글자를 Mac에서 다시 하이라이트하면 겹친 표시가 하나 더 생길 수 있습니다(데스크톱은 그 위치로 같은 하이라이트를 찾음).
