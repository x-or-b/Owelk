## 우선순위

기획서 순서보다 실제 사용 중 불편한 부분을 먼저 고칩니다. 그래서 주석·인쇄처럼 기획서 뒤쪽이거나 기획서에 없던 기능이 웹·메타데이터보다 먼저 들어왔습니다. 기능별 사용법은 [README](../README.md)와 각 문서(HIGHLIGHTS, SEARCH, RELINK, WORKSPACES, CAPTURE_NOTES, CAPTURE_TRASH)에, 변경 이력은 git 로그에 있습니다.

## 최근 단계 (2026-10-01): 규모 대비 성능·유지보수

- 출처 SHA-256을 파일 스탬프 기준으로 캐시. 재실행 시 변경 없는 PDF를 다시 읽지 않고, 캡처/하이라이트 열기·주석 로드·인쇄·검색 결과 이동도 캐시를 사용합니다. [PERFORMANCE.md](PERFORMANCE.md).
- 저장 항목 검색을 작업 스레드로 이동, 출처 확인을 저장 작업과 다른 스레드 풀로 분리.
- 두 DB에 `PRAGMA user_version` 스키마 마이그레이션 도입. 더 새로운 버전의 데이터는 열기를 거부합니다.
- QML 색상 전부를 `UiTheme.js` 토큰으로 교체(값 변경 없음), 주석 잉크 목록 단일화, C++ `.clang-format` 적용.
- 실행 순서에 따라 실패하던 탭 드래그 분할 테스트 수정.

현재 워크스페이스는 기획서의 지식 컨테이너 전체가 아닙니다. 캡처·최근 논문 목록은 앱 전체에서 공유합니다. 워크스페이스의 연결 기록 전체와 현재 열린 탭 목록도 서로 다릅니다.

## 검증

저장소 테스트와 Qt offscreen UI 테스트로 기존 PDF 렌더링·선택·검색·캡처 회귀, 탭별 위치, 닫기·다시 열기, 혼합 분할·드래그, 세션 복원, Home 지연 로드, 삭제·원본 보존을 검사합니다. 분리된 팔레트 단축키·일치 강조·안전한 텍스트 처리, 중첩 목차·썸네일·문서 전환·빈 패널, 합성 네이티브 핀치 이벤트·중심점·해상도 유지도 검사합니다. [성능 기록](PERFORMANCE.md)은 합성 offscreen 기준이며 실제 장치의 디자인·입력감 확인을 대체하지 않습니다.
