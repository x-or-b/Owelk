# PDF 본문 검색 — 2026-09-20

## 사용 범위

Home 또는 `Cmd/Ctrl+K`에서 앱으로 연 PDF의 본문을 검색합니다. 파일명·캡처 출처·워크스페이스 이름 결과도 유지합니다. 실제 폴더 트리를 펼쳤다는 이유만으로 폴더 전체를 인덱싱하지 않습니다. 업데이트 후 첫 실행에서는 기존 최근 문서·읽기 위치·워크스페이스에 기록된 PDF도 대상에 넣습니다.

본문 결과는 논문 이름, 실제 PDF 페이지 번호(1부터 시작), 일치 문맥을 표시합니다. 결과를 선택하면 파일 지문을 확인한 뒤 해당 페이지로 이동합니다. 이미 열린 논문은 탭을 추가하지 않고 기존 탭을 재사용·재로드합니다. 문장 자체의 좌표 강조는 아직 없으며 현재 문서 검색은 계속 `Cmd/Ctrl+F`입니다.

영문 대소문자를 구분하지 않는 단어 접두어 검색입니다. `counter evidence`는 같은 페이지에 두 단어의 접두어가 모두 있는 경우를 찾습니다. 단어 순서는 상관없으며 따옴표 문장 검색·OR·의미 검색 문법은 없습니다. 입력의 구두점은 단어 경계로 처리합니다. 본문은 입력 앞 512자·최대 12개 토큰을 사용합니다. 파일명·캡처·워크스페이스 결과는 종류별 최대 20개로 별도입니다.

## 논문별 묶기와 필터

- Home/Cmd+K의 본문 결과는 논문별로 묶고 각 논문의 관련도 높은 3페이지를 먼저 표시합니다. 한 번에 20개 논문이며 `More papers`로 다음 묶음을 조회합니다.
- 논문 제목 행이나 `Show all 12 matching pages in '파일명.pdf'`를 선택하면 해당 논문의 본문 검색으로 좁힙니다. 40페이지 단위로 `Next matching pages`를 제공하며, 검색어는 유지합니다. `Back`으로 이전 범위·결과 선택 위치로 돌아갑니다.
- DB 조회 단계에서 논문별 상위 결과를 선택합니다. 기존 전역 40페이지 결과를 UI에서만 잘라 묶는 방식이 아니므로 특정 논문이 다른 논문을 가리지 않습니다. 개수는 단어 출현 횟수가 아닌 일치 **페이지 수**입니다.
- `Filters`에서 `Everything / PDF text / Paper details / Captures / AI`와 논문을 고릅니다. 리더에서 연 Cmd+K는 `Current PDF`도 제공. 적용 중인 조건은 접어도 표시되며 `Clear filters`로 해제합니다.
- 검색 중 논문 제목 행은 중간 회색(#767676) 배경/흰 글자로 표시합니다. 빈 검색의 최근 문서는 일반 박스로 구분합니다. 필터·Current PDF 버튼은 높이 32px의 회색 컨트롤로 통일했습니다. 회청색은 선택·포커스·검색 일치 강조에 사용합니다. 드롭다운의 기본·호버·선택 배경/글자색을 명시해 흰색 글자가 흰색 배경에 겹치지 않게 합니다.
- 캡처에 저장한 노트도 Everything/Captures 범위로 검색하며, Note 결과를 선택하면 원문 인용과 분리된 노트 편집기를 엽니다.
- 파일명은 최근 목록과 인덱스의 문서에서 검색합니다. 논문 메타데이터의 실제 제목·저자·연도 필터는 아직 없습니다. 특정 논문으로 좁히면 워크스페이스 이름은 결과에서 제외합니다.
- 범위 변경·재검색 시 오래된 응답을 폐기합니다. 전체 인덱스 변경 중 결과/순위가 달라질 수 있으며 여러 페이지에 걸친 검색 결과 스냅샷을 고정하지는 않습니다.

## 상태와 중단

검색창 아래 **Text index**를 누르면 문서별 상태를 볼 수 있습니다.

- Searchable: 텍스트 추출이 끝났으며 본문 검색 가능. 텍스트가 있는 페이지 수를 표시합니다.
- Indexing / Checking: 한 번에 PDF 하나씩 처리하며 페이지 진행을 표시합니다.
- No extractable text: 텍스트 층이 없는 스캔·그림 PDF. OCR은 아직 없습니다.
- Missing / Failed / Locked: 이동·삭제·권한·손상·암호 문제를 표시합니다. 문제를 해결한 뒤 Retry할 수 있습니다. 암호 PDF의 본문 인덱싱은 아직 지원하지 않습니다.
- Pause / Resume: 백그라운드 작업만 일시정지·재개합니다. 진행 중인 페이지 추출이 끝난 뒤 멈춥니다. 완료된 문서는 계속 검색할 수 있습니다. 재개 시 중단 문서는 처음부터 다시 추출하며, 앱을 재실행해도 중단된 대상을 다시 시도합니다. 일시정지 설정은 실행 간 유지하지 않습니다.

최근 목록에서 제거하는 것은 검색 라이브러리에서 삭제하는 동작이 아닙니다. 이미 인덱싱한 문서의 본문은 검색에 남습니다. 검색 라이브러리에서 문서 제외·삭제하는 UI는 후속 작업입니다. 삭제된 캡처는 기존과 같이 검색에서 제외됩니다.

## 저장·성능·출처

앱 데이터 폴더에 `search.sqlite3`와 SQLite WAL 보조 파일을 추가합니다. 검색용 문서 UUID, 경로, SHA-256, 추출 버전, 페이지별 정규화된 본문을 **암호화하지 않은 로컬 데이터**로 저장합니다. 원본 PDF를 변경하거나 외부로 업로드하지 않습니다. 검색 인덱스의 문서 ID는 `owelk.sqlite3`의 공통 Document ID와 같습니다. 이전 버전에서 만든 항목은 다음 인덱스 확인 때 같은 ID로 맞춥니다. 결과 제목은 논문 정보의 제목을, 없으면 파일명을 표시합니다. Filters의 `Paper details`는 제목·저자·연도·DOI·arXiv ID·파일명을 검색합니다.

추출과 검색은 각각 별도 작업 스레드·DB 연결을 사용합니다. 검색 연결은 읽기 전용입니다. 파일명·캡처·노트·하이라이트·워크스페이스 검색도 UI 스레드가 아닌 작업 스레드의 읽기 전용 연결에서 실행합니다. 검색 저장소는 기존 세션 DB와 분리했고, WAL을 사용합니다. PDF 추출은 낮은 우선순위의 단일 작업자에서 페이지마다 짧게 양보합니다. 핀치·문장 선택 중에는 다음 페이지 추출을 기다리며, 이미 시작한 페이지 추출은 중간에 강제 종료하지 않습니다. 완료된 문서만 검색에 노출하고 문서 단위 트랜잭션으로 교체해, 취소·실패 시 반쪽짜리 결과를 노출하지 않습니다. 화면에서 검색어가 바뀌면 이전 요청의 응답은 버립니다.

인덱싱 전후에 SHA-256을 비교합니다. 재실행 시에는 저장된 파일 스탬프(크기·수정 시각·상태 변경 시각·inode)가 같고 추출 버전이 같으면 파일을 읽지 않고 건너뜁니다. 스탬프가 다르면 SHA-256을 다시 계산하고, 바이트가 같으면 추출을 생략합니다. 상태 변경 시각(ctime)은 일반 도구로 되돌릴 수 없어 수정 시각만 복원한 재작성도 감지합니다. 결과를 열 때도 현재 파일의 지문을 확인합니다. 달라졌거나 없어졌으면 이동을 차단하고 재인덱싱을 요청합니다. 파일을 옮겼다면 Text index의 Locate… 등에서 [재연결](RELINK.md)할 수 있습니다. 상시 파일 감시는 없으므로 외부 변경 직후에는 예전 결과가 보일 수 있지만 그 결과로 이동할 때 검증합니다.

페이지 텍스트 추출은 [Qt QPdfDocument](https://doc.qt.io/qt-6/qpdfdocument.html#getAllText), 검색·문맥 생성은 [SQLite FTS5](https://sqlite.org/fts5.html)를 사용합니다. 스레드별 DB 연결은 [Qt의 연결 사용 제약](https://doc.qt.io/qt-6/qsqldatabase.html#details)에 맞춰 각 작업 스레드에서 만들고 해제합니다. 줄 끝 하이픈·소프트 하이픈을 정리하고, PDFium의 [U+FFFE 하이픈 표식](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/fpdfsdk/fpdf_text_embeddertest.cpp)도 제거합니다.

## 한계와 검증

- 2단 편집·줄 끝 하이픈을 포함한 합성 PDF를 검사했지만 실제 논문의 읽기 순서·폰트 인코딩·수식 추출을 보장하지 않습니다. 일부 PDF는 글자가 분리되어 추출될 수 있어 검색 누락이나 어색한 문맥이 생길 수 있습니다.
- 한국어 등 언어별 형태소 처리, 수식 검색, OCR, 인용문 정확 일치 검색, 캡처 이미지 속 글자 검색은 후속 범위입니다.
- 문맥 강조는 입력 문자열과의 일치를 표시합니다. 악센트·유니코드 정규화로 찾은 결과는 화면의 강조 범위와 차이가 날 수 있습니다.
- 자동 테스트: 페이지·접두어·복수 단어 검색, FTS 문법 오입력, 결과 개수 제한, 원본 변경·유실·복구, UUID 유지, 재실행, 일시정지·중단 복구, 텍스트 없는 PDF, 잘못된 파일 이후 정상 파일 진행, 두 단·하이픈, 오래된 비동기 응답 무시, Home/팔레트 결과 이동·탭 재사용.
- 실제 대형 논문의 인덱싱 속도·검색 품질·동시 읽기 체감은 사용자 확인이 필요합니다. 컴퓨터 사용 MCP는 사용하지 않습니다.

추가 단기 검사: 45페이지/5페이지 논문에서 각각 상위 3페이지가 나오는지, 논문 제한·다음 40페이지 구간, 팔레트 더 보기/Back·파일명 필터, 기존 캡처 이동을 확인했습니다.
## 검색 결과 강조 수정

명령 이름뿐 아니라 Home/Cmd+K 결과의 제목·파일명·문맥도 입력과 일치하는 글자를 파란색/굵기로 표시합니다. HTML 특수문자는 먼저 이스케이프하며, 선택된 결과 배경은 밝은 회색을 사용합니다.

Qt의 `Text.StyledText`는 CSS `<span style>`을 지원하지 않으므로 지원되는 `<font color>`/`<b>` 조합으로 교체했습니다. [Qt 공식 지원 태그](https://doc.qt.io/qt-6/qml-qtquick-text.html#textFormat-prop). 회귀 테스트는 생성된 문자열뿐 아니라 실제 offscreen 화면의 제목·문맥 영역에 색상 픽셀이 있는지 검사합니다.
