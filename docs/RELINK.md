# 원본 PDF 재연결

원본 PDF를 다른 폴더로 옮기거나 이름을 바꿨을 때, 기존 탭·읽기 위치·캡처를 같은 파일의 새 경로로 연결합니다. 앱은 원본을 직접 이동·복사·삭제하지 않습니다.

## 사용

1. Recent Papers/Files의 최근 항목 또는 캡처를 우클릭 → **Locate Original PDF…**. `Text index` 상태 창의 **Locate…**, 문서 열기 오류 화면에서도 진입할 수 있습니다. 없는 최근 파일이나 캡처 원문을 열려고 하면 재연결 창을 띄웁니다.
2. **Choose PDF…**로 새 위치의 PDF를 선택합니다. 선택만으로 데이터가 변경되지는 않습니다.
3. **Verify and Relink**를 누릅니다. SHA-256이 일치할 때만 연결합니다. 검증 중에는 중복 실행·취소를 막고 결과를 기다립니다. 확인 전 Cancel은 아무것도 변경하지 않습니다.

저장 데이터는 문서 ID에 연결되어 있어 확인 후에는 문서의 경로 한 곳만 바꿉니다. 새 경로를 이미 따로 열어 둔 경우 두 항목을 합치며, 원래 문서의 읽기 위치와 논문 정보가 우선합니다(새 경로 쪽에 직접 수정한 정보만 있으면 그것을 유지). 기존 검색 인덱스·캡처·이전 재연결 기록의 지문을 사용합니다. 저장된 지문이 없어도 옛 파일을 아직 읽을 수 있으면 직접 비교할 수 있습니다. 지문도 없고 옛 파일도 사라졌다면 정확한 동일성을 확인할 수 없으므로 거절합니다. 이때 새 PDF를 별도 문서로 열 수는 있습니다.

다른 논문, 수정된 버전, 같은 내용이라도 다시 저장해 바이트가 달라진 PDF는 받지 않습니다. 한 경로에 서로 다른 버전의 지문이 남아 있어도 일괄 재연결하지 않습니다. 버전별 선택·강제 연결은 후속 범위입니다.

## 유지되는 데이터

- 현재 열린 탭·분할, 탭 ID, 각 읽기 위치·배율, 최근 닫은 탭.
- 저장된 세션과 모든 워크스페이스의 문서 참조·연결 목록.
- 최근 목록, 문서별 읽기 위치, 캡처의 원문 경로. 휴지통에 있는 캡처의 참조도 갱신하되 삭제 상태·이미지는 그대로 유지합니다.
- 기존 검색용 문서 ID. 대상 경로가 이미 인덱싱되어 있으면 원본 ID를 유지하고 중복 검색 캐시를 정리합니다.

대상 경로가 이미 최근 목록이나 워크스페이스에 있으면 소속 목록은 합칩니다. 개별 탭의 위치는 각각 유지하고, 문서별 마지막 읽기 위치가 겹치면 **재연결하는 원본의 위치**를 우선합니다. 최근 사용 시각은 더 최근 값을 유지합니다. 원본 파일이나 캡처 이미지 파일을 삭제하는 동작은 없습니다.

## 저장 안전성과 한계

기본 데이터베이스의 참조와 재연결 기록(`source_relinks`)은 한 트랜잭션으로 갱신합니다. 저장 상태 JSON이 손상되었거나 지원하지 않는 버전이면 모두 롤백합니다. 이후 오래된 UI 저장 요청이 들어와도 경로를 정규화해 옛 경로가 되살아나지 않게 합니다.

검색 캐시는 별도 데이터베이스이므로 기본 데이터와 동시에 원자적으로 커밋되지는 않습니다. 기본 DB의 영구 재연결 기록을 먼저 저장하고 검색 캐시를 순차 갱신합니다. 도중 종료되거나 캐시 갱신이 실패하면 다음 실행에서 재시도합니다. 검색 결과 열기 시 원본 지문 검증도 계속 적용합니다.

이전 경로의 리다이렉트는 유지합니다. 이미 다른 곳으로 연결했던 과거 경로를 새 대상으로 다시 선택하는 순환 연결은 현재 거절합니다. 그런 경우 새 경로를 선택해야 합니다. 자동 후보 검색, 폴더 일괄 재연결, 리다이렉트 해제·버전별 재연결은 후속 작업입니다.

자동 테스트는 임시 생성 PDF만 사용합니다. 동일 파일·다른 파일·지문 없음, 대상 중복, 캡처 휴지통, 손상된 저장 상태 롤백, 재실행, 탭/분할/닫은 탭 유지, 확인·취소·실패 설명을 검사합니다. 실제 파일 선택 대화상자는 사용자가 확인합니다.
