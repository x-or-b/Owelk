# 다음 개발 묶음: 탭과 임의 개수 분할

## 현재 상태

화면은 `leftReader`와 `rightReader` 두 개로 고정되어 있고, 세션도 두 문서만 저장합니다. 같은 논문의 서로 다른 페이지를 보는 것은 가능하지만, 새 분할을 계속 추가하거나 문서 제목을 드래그해 분할하는 기능은 없습니다.

선택 높이 고정, 수식키+휠 확대, 필요할 때만 여는 검색창, 영어 UI, 하단 아이콘을 통한 Files / Captures 패널의 닫기·좌우 이동·복원, 읽기 전용 폴더 탐색을 구현했습니다. Home의 검색·이어 읽기·최근 목록과 초기 읽기 워크스페이스도 연결했습니다. 검색은 아직 파일명·캡처 출처·워크스페이스 이름 범위입니다. 사이드 패널 이동과 문서 드래그 분할은 별개입니다. 아래 작업은 앞으로 구현할 내용이며, 완료 표시가 아닙니다.

## 순서와 완료 조건

### 1. 탭별 상태

- 안정적인 tab ID와 source URL을 분리합니다. 같은 PDF를 여러 탭에서 열어도 읽던 위치·배율은 독립적이어야 합니다.
- 그룹은 tab 목록과 활성 tab ID를 가집니다. 선택/검색 같은 일시적인 UI 상태와 저장할 읽기 상태를 구분합니다.
- 문서를 교체해도 기존 문서의 읽던 위치가 사라지지 않도록 하고, 이동·닫기 전에 상태를 반영합니다.
- 비활성 문서는 필요할 때 로드하여 탭 수가 늘어도 모든 페이지를 동시에 렌더링하지 않습니다.

### 2. 분할 트리와 세션 마이그레이션

- 잎 노드는 탭 그룹, 내부 노드는 분할 방향·자식·비율을 저장합니다.
- 고정 2개 제한을 없앱니다. 실제 가능한 수는 메모리·화면 크기의 제약을 받으며, 화면보다 많은 분할을 강제로 밀어 넣는 방식은 피합니다.
- 마지막 탭을 닫으면 빈 그룹을 제거하고, 자식 하나만 남은 분할 노드는 합칩니다. 활성 그룹도 유효한 이웃으로 옮깁니다.
- 기존 버전 1의 left/right 세션을 새 버전으로 변환합니다. 이전 읽던 위치는 보존하고, 변환 실패 시 기존 데이터를 덮어쓰지 않습니다.
- 검증: 3개 이상 분할, 혼합 가로·세로 분할, 분할 닫기, 재실행 복원, 같은 원본의 독립 위치, 기존 세션 변환.

### 3. 드래그로 탭 이동·분할

- PDF 본문 드래그는 계속 텍스트 선택에 사용합니다. 탭/문서 제목이 드래그 손잡이입니다.
- 그룹의 좌·우·상·하 가장자리에 놓으면 해당 방향으로 새 분할을 만듭니다.
- 중앙에 놓으면 해당 그룹에 탭을 이동하고, 탭 표시줄 안에서는 순서를 바꿉니다.
- 놓을 위치를 미리 표시하고, Esc 또는 영역 밖에서 놓으면 원상태를 유지합니다.
- 드롭에 성공한 뒤에만 모델을 변경합니다. 읽던 위치를 유지하고 중복/소실되는 탭이 없어야 합니다.
- 같은 논문의 다른 위치를 비교하는 명시적인 '복제해 분할' 기능을 별도로 둡니다.
- OS의 별도 창으로 떼어내기는 이 묶음에서 제외합니다.
- 검증: 드롭 성공/취소, 마지막 탭 이동, 같은 그룹 내 순서 변경, 텍스트 선택과 충돌 없음, 이동 후 세션 복원.

## 별도 성능 작업: 핀치 확대

제스처 중에는 기존 페이지 이미지를 임시로 확대하고, 종료 후 목표 해상도로 다시 렌더링합니다. 손가락 중심의 문서 좌표 유지, 배율 상·하한, 연속 제스처, 선택 표시 정렬, 렌더 작업 누적 방지를 함께 검증합니다. 큰 PDF에서 지연과 메모리를 측정합니다.

## 사람에게 요청할 확인

실제 마우스·트랙패드, macOS/Windows/Linux에서의 입력감과 레이아웃 평가는 사용자가 직접 확인합니다. 자동 테스트는 offscreen에서 실행하고, 컴퓨터 사용 MCP로 사용자의 화면을 조작하지 않습니다.
