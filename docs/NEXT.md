## 1. 읽기 품질 마무리

- 핀치 구현은 자동 검증 완료. 실제 macOS 트랙패드에서 연속 제스처·선택/캡처 표시 정렬·최종 선명도를 확인할 것.
- 실사용 PDF와 여러 분할에서 초기 표시 지연·스크롤·선택 지연·GPU 프레임·메모리 측정. 합성 offscreen 기준은 실제 체감 성능을 대신하지 않음.
- 탭 탐색 단축키, 드래그 가장자리 자동 스크롤.
- 활성 그룹이 바깥 스크롤 영역 밖에 있을 때 자동으로 보이게 이동하는 UX.
- macOS 실기기 검증 이후 Windows/Linux 빌드·Ctrl+휠·Ctrl+W 검증.

완료 조건: 선택·캡처 좌표를 유지하면서 핀치가 연속적으로 보이고, 대표적인 큰 PDF/여러 분할에서 측정 결과를 남길 것.

수동 확인할 조합: PDF 열기 → Document의 Outline/Thumbnails 이동 → 분할·활성 탭 전환 → 핀치 후 문장 선택/영역 캡처 → 마지막 탭 닫기·다시 열기. 명령 팔레트에는 `dupli right`, `capt`, `outli`를 입력해 후보와 강조를 확인할 것.

## 2. 라이브러리 본문 검색 — 기본 구현 완료, 품질 개선 남음

- 구현: 페이지별 추출·백그라운드 FTS5, 검색용 문서 ID/경로/지문/버전, 진행·중단·재시작, 페이지·문맥 결과, 원본 검증 후 페이지 이동.
- 구현: 현재 PDF 검색(Cmd/Ctrl+F)과 전체 검색(Cmd/Ctrl+K) 구별. 기존 파일명·캡처 출처·워크스페이스 이름 검색 유지.
- 검증: 합성 2단·하이픈·텍스트 없는 PDF, 비정상 PDF, 파일 변경/유실/복구, 오래된 검색 응답 폐기. 실제 PDF의 수식·폰트·읽기 순서는 수동 검증 필요.
- 후속: 인덱스에서 문서 제외, 문장 좌표 강조, 라이브러리 Document ID를 기존 캡처·탭 참조까지 통합. OCR은 별도 범위.

### 검색 묶기·기본 필터 — 구현 완료

- 논문별 묶고 각 논문에서 관련도 높은 3개 페이지를 먼저 표시. 검색 자체를 3개로 제한하지 않음.
- `Show all … matching pages in '파일명.pdf'`로 해당 논문에 검색 범위를 제한한 결과를 펼치거나 전환. 검색어와 돌아갈 위치를 유지. 의미가 모호한 `…`만 쓰지 않음.
- DB에서 문서별 상위 결과를 고르고 20개 논문 단위로 조회합니다. 논문을 선택하면 40페이지 단위로 조회합니다.
- 현재 검색 결과 단위는 페이지이며 단어의 전체 등장 횟수가 아님. 개수 표시는 `matching pages`로 명시하고, 조회하지 않은 전체 개수를 추정값처럼 확정해서 보여주지 않음.
- 기본 필터는 범위(전체 / 현재 논문 / 선택한 논문)와 대상(본문 / 파일명 / 캡처)으로 분리. Filters로 펼치고, 접힌 상태에서도 조건 요약·Clear filters를 표시합니다.
- `PaperA`만 골라 `occu`를 검색할 수 있게 하되 복잡한 검색 문법을 먼저 요구하지 않음. 이미 열린 현재 논문만 단순 검색하려면 지금도 Cmd/Ctrl+F를 사용할 수 있음.
- 논문 메타데이터의 제목·저자·연도 검색, `title:` 같은 고급 문법, 의미 검색은 이후. 현재 검색 결과의 제목은 대부분 파일명이므로 실제 논문 제목 필터와 구분할 것.

참고 패턴: [VS Code의 파일별 검색 결과와 포함/제외 범위](https://code.visualstudio.com/docs/editing/codebasics#_search-across-files). 정확한 구현 범위·조회 한계는 [SEARCH.md](SEARCH.md)를 따릅니다. 자동 검사는 변경 부분만 짧게 실행하고 실제 디자인·입력감은 사용자가 확인합니다.

완료 조건: 이름이 아니라 본문 문장으로 여러 논문을 찾고, 결과에서 정확한 페이지로 이동. 인덱싱 중에도 읽기·선택이 끊기지 않을 것.

기본 검색·이동과 자동 회귀 검사를 구현했고 사용자가 정상 작동을 확인했습니다. 다양한 실제 논문의 검색 품질·읽기 체감 평가는 계속합니다.

## 확인 방식

최근 수정 확인: HEIC 선택 → 미리보기·방향·저장, 선택 해제 후 하이라이트 우클릭 → Change Color 위치, 글자/여백 사이 커서 전환, 앱 완전 종료·재실행 후 인쇄창 열기/취소, 시험용 Workspace 관리·삭제 확인창 정렬. HEIC 테스트 파일 생성에는 macOS 시스템 코덱 접근이 필요하며, offscreen 인쇄창 검사는 실제 프린터 출력 검증을 대신하지 않습니다.

자동 테스트는 임시 데이터와 Qt offscreen 창에서 실행합니다. 컴퓨터 사용 MCP는 사용하지 않습니다. 실제 화면·마우스·트랙패드 사용성은 사용자가 직접 확인합니다. 네이티브 다중 창과 탭을 OS 창으로 떼어내기는 아직 범위 밖입니다.
